# AIリリースチェック(AI Release Check)

AIで曲を作る人のための、配信前の確認ページ(非公式・各配信先と提携していません・法律の助言ではありません)。

AIで曲を作る人が、配信の前に「配信先ごとの決まり」に合っているかを確かめるための道具。
ブラウザだけで動き、入れた曲名・歌詞・画像の情報は外に送らない(本体は通信も保存もしない)。

## いまあるもの
- `rules.json` — 決まりの表(配信先5つ・23項目 + JASRAC の作品届 3項目)。各項目に公式の案内のURL・節・確かめた日
- `check.js` — チェックの本体。ブラウザでも node でも動く
  - `check(rules, song)` → 配信先ごとに「通る/危ない/断られる」と、項目ごとの理由・直し方・出典
  - `tidy(song, rules)` → 登録情報の整え(曲名の feat. 表記・全角の英数字、歌詞の行末の句点と空行、ジャケットの大きさの目安)
  - `productionRecord(song, report, 日付)` → 指摘されたときに出せる「制作記録」(道具・版・プラン・自分の作業・プロンプト・歌詞・チェック結果)
  - 0.4.0 で追加: NexTone の作品届(選んだときだけ)。NexTone の管理委託契約約款(2026-02-01 改訂)と FAQ にはAIの作品の扱いが書かれていないので、AIを使った作品は届ける前に問い合わせるよう示す。約款 第7条(権限と第三者の権利を侵害しない保証)への備えとして制作記録を勧める。TuneCore Japan の配信規約(2025-12-22 改定)の本文にAIの条項が無いことも書き添えた(配信規程は未確認のまま)
  - 0.3.0 で追加: JASRAC の作品届(選んだときだけ)。歌詞も曲もAIの自律生成なら管理されない・一方だけAIなら作品届に「作詞(又は作曲):AI 自律生成」と書き管理率を表どおりに示す・人の寄与を保証する義務(約款 第9条)への備え。出典は JASRAC の「AIを利用した作品の取り扱い(ガイドライン)」(2026-03-30 更新)。制作記録に作詞・作曲の担当を足した
  - 0.2.0 で追加: 曲名・名前に訳を横に並べる書き方(Apple Music・Spotify)、Spotify の曲名の feat.(Apple Music と扱いが逆なので配信先ごとに出す)
- `quota.js` — 無料の回数(1か月3曲。端末の中だけで数え、同じ曲は数えない。保存が使えない端末では数えずに使える)
- `sns.js` — YouTube の題名・説明文・タグ、X・TikTok の投稿文の型(日本語・英語)。AIを使ったことは隠さずに書く
- `page/index.html` — ページ(スマホで使える・外のものを読み込まない・注意書きと「公式ではない」旨)
- `build_page.py` — 上の部品を埋め込んだ1つのファイル `dist/index.html` を作る(Cloudflare Pages にそのまま置ける)
- `index.html` — 上の `dist/index.html` と同じもの(公開用フォルダに置く。開くだけで使える)
- `LICENSE` — MIT

## 使い方
1. `index.html` をブラウザで開く(またはどこかの静的な置き場に置く)
2. 曲名・アーティスト名・使ったAI・自分がした作業・歌詞・ジャケットの大きさと文字・配信先を入れる
3. 配信先ごとの「通る/危ない/断られる」と直し方を見る。整えた曲名・歌詞と制作記録をコピーして使う

## できないこと・限界
- 音声は調べない(AIの判定・声が似ているかは見ない。入力で「似せた」と答えた場合だけ見る)
- 決まりは2026-11-11 時点で公式の案内を読んで書いたもの。配信先が決まりを変えると古くなる。各項目の checked(確かめた日)を見る
- 公式に名指しの無い当てはめは「NEXUS の読み方」と書いてある。公式で確かめられない項目は「未確認」と出し、「断られる」にはしない
- 何曲・何秒で迷惑扱いになるかの数は公式に無いので、数では判定しない
- 審査に通ることを約束するものではない

## 安全
- 通信しない・入れた情報を保存しない(無料の回数だけ端末の中に数を残す)。外のスクリプト・フォント・画像を読み込まない
- 実在の歌手に似せた声・名前を使うことは勧めない(許可の無いまま似せたと入れると指摘する)

## 決まりの扱い
- 公式で確かめられなかった項目は `status: unverified`。結果は「未確認」と出し、「断られる」にはしない
- 入力が無い項目は「目で確かめる(manual)」と出し、勝手に合格・不合格にしない
- 公式の案内に名指しが無い当てはめ(例: AIの道具の名前をアーティスト欄に書く)は `basis` に「NEXUS の読み方」と書く
- 数のしきい値(何曲・何秒で迷惑扱い)は公式に書かれていないので、数では判定しない
- 法律の助言ではない。最終判断は各配信先の案内で

## 入力の形(例)
```json
{
  "title": "Walking In The Rain", "artist": "MIRO", "featuring": [],
  "ai": {"tool": "Suno", "version": "v5", "plan": "paid", "created": "2026-11-10"},
  "human_work": ["作詞"], "lyrics": "…",
  "artwork": {"width": 3000, "height": 3000, "format": "jpg", "text_kinds": []},
  "vocals": {"sounds_like": ""}, "release": {"duplicate": false},
  "disclosures": {"youtube_altered": true, "credits_ai": true},
  "platforms": ["apple_music", "spotify", "youtube", "tunecore_japan", "distrokid"]
}
```

## テスト
- `python -m unittest discover -s tests`(rules.json の形と、node があれば check.js のテスト)
- `node --test tests/test_check.mjs`(check.js のテスト25件)
- `node --test tests/test_page.mjs`(回数・SNSの型・ページのテスト5件)
